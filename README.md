# HTTP Download Benchmark

Консольная утилита на **Python 3.11+** для измерения загрузки заданного HTTP(S)-ресурса. Выполняет **ровно 10 последовательных GET-запросов** при успешном замере, полностью читает каждый ответ и выводит среднее время, общий объём и скорость в MB/s и Mbps.

**Без внешних зависимостей.** Загрузка идёт в память блоками по 64 КиБ; файл не сохраняется на диск и не накапливается целиком в RAM.

> Скорость загрузки конкретного URL не является универсальной скоростью интернет-канала. Результат зависит от сервера, маршрута, задержек, TLS, прокси, ограничений CDN и размера ответа.

## Возможности

- Строго последовательное выполнение: следующий GET начинается после чтения и закрытия предыдущего ответа.
- Подсчёт фактически прочитанных байтов, проверка полноты по `Content-Length`, поддержка chunked и ответов до закрытия соединения.
- Полное время запроса через монотонный `time.perf_counter()`, включая подключение, заголовки, тело и закрытие ответа.
- Прогресс `1/10`–`10/10`, время и объём каждого ответа, итоговая таблица, минимум и максимум времени.
- Обработка HTTP-ошибок, обрывов, тайм-аутов, ошибок TLS и небезопасных перенаправлений.
- ASCII-интерфейс без цветов: читается в Windows и при перенаправлении вывода.

## Требования

- Python **3.11 или новее**, только стандартная библиотека.
- Для внешнего ресурса — сетевой доступ; для HTTPS — доверенная цепочка сертификатов в Python.
- Git нужен только для работы с репозиторием, GitHub CLI — только для публикации.

Устанавливать пакеты через `pip` не требуется.

## Быстрый запуск на Windows

Откройте PowerShell в каталоге проекта:

```powershell
python --version
python speed_test.py "https://example.com/large-file.jpg"
```

Замените пример URL прямой ссылкой на существующий ресурс. Домен `example.com` здесь обозначает пример адреса, наличие файла не предполагается. Если используется Python Launcher, можно вызвать `py -3.11` вместо `python`.

Увеличить бюджет запроса для большого файла:

```powershell
python speed_test.py "https://example.com/large-file.jpg" --timeout 120
python speed_test.py --help
```

Воспроизводимый локальный запуск без внешней сети: в первом терминале из каталога проекта запустите сервер только на loopback:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Во втором терминале:

```powershell
python speed_test.py "http://127.0.0.1:8000/README.md"
```

После проверки остановите сервер через `Ctrl+C`. Локальный результат характеризует передачу по loopback, а не интернет-соединение.

## Linux / macOS

```bash
python3 --version
```

URL берите в кавычки: символы `&`, `?` и другие символы могут интерпретироваться оболочкой. Допускаются только ASCII URL без логина и пароля; для Unicode-пути используйте percent-encoding, для домена — IDNA. Фрагмент `#...` удаляется перед запросом.

## Методика измерения

1. Проверить URL и тайм-аут до первого подключения.
2. Для каждого из 10 запросов включить `perf_counter()` непосредственно перед открытием соединения.
3. Открыть ответ через `urllib.request`, читать `read1(65536)` до конца, суммировать длины полученных блоков и закрыть ответ через `with`.
4. Проверить полноту ответа; только после этого записать результат и перейти к следующему GET.
5. Рассчитать сводку только при наличии всех десяти успешных измерений.

Автоматических повторов, предварительного HEAD-запроса и прогрева нет. `urllib` использует новые соединения с `Connection: close`: в измерение входит стоимость их установки. Создание запроса, печать прогресса и вычисление сводки не входят в сумму измеренных интервалов. Тело ответа может различаться между запросами: каждый раз считаются реально полученные байты.

### HTTP-перенаправления

Для честного измерения **10 полных загрузок файла** передавайте прямой URL ресурса,
который возвращает `200 OK`, без цепочки редиректов. Автоматические переходы
отключены. При ответе `301/302/303/307/308` инструмент прекращает измерение с
понятной ошибкой и без итоговой скорости. Это предотвращает смешивание тела
ответа-перенаправления с байтами скачиваемого файла. Для ресурса, который перенаправляет
клиента, сначала получите его конечный прямой URL.

### Кеширование и сжатие

Отправляются `Cache-Control: no-cache, no-store, max-age=0`, `Pragma: no-cache` и `Accept-Encoding: identity`. Локального кеша у этой утилиты нет; HTTP 304 считается ошибкой. URL не модифицируется случайными query-параметрами, чтобы не ломать подписанные ссылки.

Эти заголовки не гарантируют обход кеша сервера или CDN. Если сервер игнорирует `identity` и присылает сжатое представление, `urllib` не распаковывает его: считаются прочитанные байты сжатого тела.

## Формулы и единицы измерения

Для запроса `i`: `b_i` — фактически прочитанные байты тела, `t_i` — полный измеренный интервал в секундах, `N = 10`.

| Показатель | Формула / определение |
| --- | --- |
| Общий объём `B` | `sum(b_i)` байт |
| Суммарное время `T` | `sum(t_i)` секунд |
| Среднее время запроса | `T / 10` секунд |
| Скорость, bytes/s | `B / T` |
| Скорость, MB/s | `B / T / 1_000_000` |
| Скорость, Mbps | `B / T * 8 / 1_000_000` |
| MB | 1 000 000 байт, десятичный мегабайт |
| MiB | 1 048 576 байт, двоичный мебибайт; в итоговой таблице не используется |
| КиБ / KiB | 1 024 байта; блок чтения 64 КиБ = 65 536 байт |

Скорость рассчитывается как **отношение сумм**, а не среднее арифметическое скоростей отдельных запросов. Заголовки HTTP, chunked-разметка, TLS и TCP/IP не входят в объём полезного тела, но время их передачи влияет на интервал. Пустые корректные ответы дают 0 байт и нулевую скорость; неполные измерения не дают сводки. Расчёты выполняются без промежуточного округления; вывод округляется до шести знаков после точки.

## Тесты

Из корня проекта:

```powershell
python -m unittest discover -s tests -v
```

Тесты не требуют интернета. Локальный `ThreadingHTTPServer` слушает только `127.0.0.1` на свободном порту; его параллельная обработка нужна, чтобы обнаружить возможное наложение запросов клиента. В коде самой утилиты нет потоков или asyncio.

Проверяются точные десять GET, отсутствие перекрытия загрузок, чтение последнего байта, подсчёт объёма, формулы, большие ответы с ограничением памяти, пустые и chunked-ответы, 404/500, обрыв, тайм-аут, медленная передача, перенаправления без ложной сводки, некорректные URL, закрытие ответа и коды CLI. Ошибки TLS и некоторые аварийные сценарии дополнительно моделируются через `unittest.mock`; обычные HTTP-сценарии используют реальные сокеты.

Фактически выполненные проверки и ограничения среды указаны в [VERIFICATION.md](VERIFICATION.md).

## Обработка ошибок

| Exit code | Значение |
| --- | --- |
| `0` | Все 10 запросов завершены и сводка рассчитана; также `--help` |
| `1` | Сетевая/HTTP/TLS-ошибка, неполное тело, неправильный ответ, редирект или превышение бюджета |
| `2` | Ошибка аргументов: URL, тайм-аут, отсутствующий или неизвестный параметр |
| `130` | Прерывание `Ctrl+C` во время измерения |

Первая ошибка останавливает выполнение без повторов. Предыдущие строки прогресса остаются в stdout, сообщение с номером неудачного запроса выводится в stderr. Итоговой таблицы и скорости при этом нет. Ответ 206 / `Content-Range` отклоняется, чтобы частичный ресурс не выдавался за полную загрузку. Неверные или неоднозначные заголовки длины тоже считаются ошибкой.

`--timeout` по умолчанию равен 30 секундам и принимает конечное положительное число до 86 400 включительно. Он задаёт тайм-аут блокирующих операций сокета и проверяемый бюджет полного запроса. Бюджет проверяется после открытия ответа и между чтениями `read1`, поэтому сервер, непрерывно отдающий по байту, не может бесконечно продлевать загрузку обычного тела.

## Известные ограничения

- Это HTTP-бенчмарк конкретного ресурса. Параллельные потоки, несколько серверов и подбор оптимальной нагрузки для измерения всего интернет-канала не реализованы.
- `--timeout` не является жёстким системным дедлайном: уже выполняющаяся операция может выйти за общий бюджет до своего socket timeout. Системный DNS и медленная передача заголовков / chunked-метаданных могут задержать проверку бюджета. Строгая межплатформенная отмена блокирующего вызова потребовала бы отдельного процесса или иной модели ввода-вывода. При необходимости замер можно прервать `Ctrl+C`.
- Без `Content-Length` и chunked-разметки закрытие соединения служит концом тела; отличить штатное закрытие от усечённого файла средствами HTTP невозможно. Целостность содержимого по хешу не проверяется.
- При наличии `Content-Length` проверяется фактический размер, при chunked — завершённость HTTP-разметки. Одинаковые повторяющиеся `Content-Length` тоже отклоняются: это намеренно строгая обработка неоднозначного ответа.
- Сервер может игнорировать запросы обхода кеша и управлять размером/сжатием ответа. Очень маленькие файлы преимущественно измеряют задержки, а не устойчивую пропускную способность.
- Авторизация, cookies и отключение проверки TLS не поддерживаются. Прокси учитываются стандартным поведением `urllib`, включая настройки среды и ОС.
- Локально проверена Windows с Python 3.11 и 3.14. Linux/macOS не запускались в этой среде.

```text

tests/test_speed_test.py  # локальный сервер, интеграционные и модульные тесты
README.md                # запуск и методика
```

HTTP-чтение (`download_once`), управление десятью запросами (`run_benchmark`), чистые расчёты (`calculate_statistics`) и отображение разделены функциями в одном небольшом модуле. Две неизменяемые dataclass хранят измерение и сводку.
