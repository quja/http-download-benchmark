# Проверка решения

Проверено **17 ноября 2026 года**, Windows, Python **3.11.0** и **3.14.2**. Ниже указаны выполненные операции, без заявлений о проверках на других ОС или о публикации в GitHub.

## Исходные проверки, указанные автором версии до ревью

В исходном отчёте проекта указано выполнение на обоих интерпретаторах:

```text
python -W error::ResourceWarning -m unittest discover -s tests -v
py -3.14 -W error::ResourceWarning -m unittest discover -s tests -v
```

Результат на каждом: **36 тестов, OK, exit code 0**. Последний зафиксированный прогон занял 3,325 с на Python 3.11 и 4,434 с на Python 3.14. Внешняя сеть для этих тестов не используется. Проверка форматирования и линтер Ruff 0.17.3 также завершились с кодом 0:

```text
ruff check --isolated --target-version py311 --select E4,E7,E9,F,I,UP,B .
ruff format --isolated --check .
```

Ruff — дополнительный локальный инструмент проверки; он не нужен для запуска утилиты или тестов.

## Отдельный реальный запуск CLI, указанный в исходном отчёте

Вне набора unittest поднят `http.server.SimpleHTTPRequestHandler` на `127.0.0.1`, запущен отдельный процесс `python speed_test.py <локальный URL README.md>`, затем независимо прочитаны журнал обращений сервера и размер файла на диске.

- Сервер зарегистрировал **ровно 10 GET** к `/README.md`.
- Размер файла на момент запуска — **18 299 байт**.
- Программа вывела **182 990 байт**, то есть точную сумму десяти тел ответа.
- Процесс завершился с кодом **0**, stderr пуст, итоговая таблица выведена.

Это проверка работоспособности и согласованности подсчёта, а не замер скорости интернета. Отдельный тест с многопоточным сервером проверяет отсутствие одновременных загрузок; ещё один тест загружает десять ответов по 5 МиБ + 17 байт и проверяет пик Python-аллокаций менее 3 МиБ через `tracemalloc`. Такой порог относится к отслеживаемым аллокациям, а не к полному RSS процесса.

## Повторное ревью и исправления

Проведён отдельный проход по коду после первого работающего варианта. Это самопроверка AI-агента, а не ревью другим разработчиком.

| Риск | Реализация / проверка |
| --- | --- |
| Скрытые дополнительные запросы при редиректе | Автоматические редиректы отключены; при HTTP-перенаправлении измерение завершается без сводки, чтобы не смешивать тело 302 с загружаемым файлом. |
| Ложный успех при усечённом теле | Фактический объём сверяется с `Content-Length`; повреждённая chunked-передача завершается ошибкой. |
| Частичный HTTP-ответ вместо всего ресурса | 206 / `Content-Range` отклоняются. |
| Бесконечное медленное тело | Чтение через `read1` и проверки общего бюджета; тест сервера, посылающего по байту. Границы этого подхода описаны в README. |
| Ошибка формулы скорости | Тест с разными длительностями отличает отношение сумм от среднего отдельных скоростей. |
| Большой расход памяти | Ограничение блока 64 КиБ, интеграционный тест большого тела и отдельная проверка размера каждого чтения. |
| Незакрытый ответ при исключении | Контекстный менеджер; проверены исключения чтения и вызов выхода из контекста. |
| Переполнение системного timeout | При ревью добавлена верхняя граница 86 400 секунд, слишком большие и нечисловые значения отклоняются до подключения. |
| Разное поведение Windows при недоступном порте | Первоначальное ожидание ECONNREFUSED скорректировано: реальная ОС может вернуть timeout. Сообщение об отказе/тайм-ауте проверяется, ошибки не игнорируются. |
| Кодировка консоли | Интерфейс и таблица состоят из ASCII; CLI-тест декодирует stdout/stderr как ASCII. |
| Несуществующая успешная сводка | HTTP-ошибка, поздний сбой, неполный ответ и timeout проверены через CLI; код 1, без таблицы скорости. |

## Проверка внешнего HTTPS

Команда `python speed_test.py https://example.com --timeout 15` выполнена на обоих интерпретаторах. Оба запуска завершились на первом запросе с **exit code 1** и `CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`. Сводка не выводилась.

Поэтому успешный внешний HTTPS-бенчмарк в этой среде **не подтверждён**. Код использует стандартную проверку сертификатов; её отключение и изменение доверенных сертификатов ОС не выполнялись. Обработка TLS-ошибки дополнительно покрыта модульным тестом.

## Независимое повторное ревью после упаковки

После изучения ZIP обнаружена концептуальная неточность: первая версия считала тело HTTP 302
в общей статистике скорости как одно из 10 скачиваний. Теперь редирект завершает измерение
ошибкой с рекомендацией использовать конечный URL; положительные измерения всегда содержат
ровно десять завершённых ответов выбранного ресурса.

Этот раздел не отменяет исходные заметки о проверках в Windows; после изменения кода
проведён новый независимый прогон тестов в доступной Linux-среде, Python 3.13.5.
Независимо выполнена команда `python -W error::ResourceWarning -m unittest discover -s tests -v`
на Linux/Python 3.13.5: **37 тестов, OK** (добавлена проверка отказа от редиректа через CLI).
Проверки изменённого варианта под Windows 3.11/3.14 пока не повторялись.
Остальные сведения об исходной среде в этом документе — отчёт автора архива,
а не результаты независимого запуска на той же ОС.
